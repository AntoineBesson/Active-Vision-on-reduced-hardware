# Method 3 (motion-gated previous-frame reuse) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build, bound, tune on train and report once on val a method that
keeps the previous frame's prediction, warped by a global homography, and
recomputes only the cells where the homography-aligned frame difference
shows motion, with a full-pass fallback and an optional low-res pass (3b).

**Architecture:** `src/reuse/` holds the motion ops, the deployable
`MotionReuseMethod` and an exact replay over per-frame caches. The GPU-heavy
stages (per-frame caches, replay sweeps, latency tables) run on the Colab
T4 from notebooks, one chunk of clips per session. The laptop runs the CPU
tests, data packaging, merges, finalists and the report.

**Tech Stack:** Python, PyTorch, OpenCV (`opencv-python-headless`),
NumPy, pytest, Colab notebooks generated by scripts.

**Spec:** `docs/superpowers/specs/2026-11-02-method3-motion-reuse-design.md`

**Gate:** start Task 1 only once the Method 2 finalists' T4 `final` runs
are in and ingested (Task 12 of the Method 2 plan).

## Global Constraints

- Branch: a new branch `motion-reuse` cut from `foveation-no-memory` after its PR merges, else from `foveation-no-memory`.
- Metric: standard 19-class mIoU only; per-class IoUs reported.
- Two latency judges: mean and p95 per-frame T4 latency over all frames of all clips; both trade-off readings against both.
- Tune on VPS train; VPS val is run once, on frozen finalists only. No probe, plot or check on val before that (Method 2's breach is not repeated).
- Deterministic everything; fixed seeds (`cv2.setRNGSeed(0)`, torch seed 0).
- GPU work runs on the Colab T4 (user's preference, 2026-11-02: the laptop GPU overheats). The laptop runs CPU-only work and the test suite.
- Accuracy passes in fp32; latency fp16 with CUDA graphs, batch 1.
- Glimpse margin 32, glimpse model = full-pass model, Method 2's replace rule.
- No frame skipping, no memory older than the previous frame, no learned flow, no retraining.
- Every try, failures included, goes in `results/method3/TRIES.md`.
- A latency number comes only from the T4 floor tables or a T4 run, and always includes homography, motion map and warps.

## Review Focus

1. **Homography fails** (blur, glare, textureless frame: < 8 good matches, or a degenerate H): the method must fall back to H = identity, count the frame in its stats, and never produce NaN or crash. Pinned in Task 2.
2. **Warp leaves pixels with no source** (borders after a turn): those pixels count as moving, and the warped memory still carries a valid label there (border replication), so no prediction ever holds 255. Pinned in Task 3.
3. **A train clip without 30 consecutive frames** in the raw download: packaging refuses it, naming the clip and the missing frame. Pinned in Task 1.
4. **Chunk results merged twice, or a chunk missing**: merge refuses duplicate clip ids and lists missing ones. Pinned in Task 7.
5. **An unmeasured latency point** (a full scale, k or part with no T4 entry): prediction raises naming `latency_floor`, never extrapolates. Pinned in Task 5.

### Task 2: Motion ops: homography, warp, motion map, moving cells

**Files:**
- Create: `src/reuse/__init__.py`, `src/reuse/motion.py`
- Modify: `pyproject.toml` (optional dependency group `reuse = ["opencv-python-headless"]`)
- Test: `tests/test_reuse_motion.py`

**Interfaces:**
- Consumes: `foveation.ops.GlimpseGrid`.
- Produces (all in `reuse.motion`):
  - `MOTION_FACTOR = 4` (motion runs at 1/4 resolution: 256×512).
  - `to_gray_small(frame: Tensor[1,3,H,W] in [0,1], factor: int = MOTION_FACTOR) -> Tensor[h,w] float32` (area downsample, BT.601 luma).
  - `estimate_homography(prev: Tensor[h,w], cur: Tensor[h,w], method: str = "orb") -> Tuple[Tensor[3,3] float64, int]`: H maps *full-resolution* prev pixel coordinates onto cur; second value = RANSAC inliers. `method="orb"`: OpenCV ORB (1000 features) + BF Hamming matching + `findHomography(RANSAC, 3.0)`, `cv2.setRNGSeed(0)` before. `method="iclk"`: GPU inverse-compositional Lucas–Kanade on a 64×128 pyramid level, 30 fixed iterations, torch only. Fewer than 8 inliers or a non-finite / near-singular H (|det| < 1e-3 or > 1e3 on the 2×2 block) → identity and inliers 0.
  - `warp(x: Tensor[N,C,H,W], H: Tensor[3,3], mode: str) -> Tuple[Tensor, Tensor[H,W] bool]`: backward map with `grid_sample(align_corners=False, padding_mode="border")`; returns the warped tensor and the valid mask (source inside the frame). H is given at full resolution and rescaled internally for other sizes.
  - `motion_map(prev: Tensor[h,w], cur: Tensor[h,w], H: Tensor[3,3]) -> Tensor[h,w] uint8`: |cur − warp(prev)| × 255, 5×5 box blur, invalid pixels set to 255.
  - `moving_cells(motion: Tensor[h,w] uint8, grid: GlimpseGrid, theta: int, rho: float) -> Tensor[num_cells] bool`: share of each cell's inner in-frame pixels (at motion resolution) with motion > θ, compared to ρ.

### Task 3: `MotionReuseMethod` (the deployable method)

**Files:**
- Create: `src/reuse/method.py`
- Test: `tests/test_reuse_method.py`

**Interfaces:**
- Consumes: Task 2; `foveation.pipeline.context_pass, glimpse_labels`; `foveation.ops.gather_crops, paste_labels`; `eval.harness.FrameMethod, CostLedger`.
- Produces:
  - `@dataclass(frozen=True) MotionReuseConfig(full_scale: float, glimpse_size: int, theta: int, rho: float, tau: float, ctx_scale: Optional[float] = None, margin: int = 32, homography: str = "orb")`. `ctx_scale=None` is 3a; a value is 3b with the conf fusion. `tau=1.0` never falls back. `name() -> str` stable id, e.g. `3a/f1/g384/t20/r0.05/u0.4`.
  - `class MotionReuseMethod` implementing `FrameMethod`: `__init__(backbone, cfg, precision="fp32", allow_any_frame_size=False)`, `reset(clip)`, `predict(frame, t, ledger) -> Tensor[H,W]`, `describe()`, `latency_fns(frame_size, device)`. After each `predict`, `self.last_step = {"fallback": bool, "moved_cells": int, "num_cells": int, "inliers": int}`.
  - Memory: label map (H, W) uint8 at full resolution and confidence (h, w) uint8 at motion resolution: round(255 · max prob) of the pass's logits resized bilinearly to (h, w). This quarter-resolution uint8 confidence is what both the method and the replay use (settles the spec's storage call).
  - Per frame, as in the spec: frame 0 → full pass at `full_scale`, memory = its labels and confidence. Later frames → homography, motion map, moving cells; share of moving cells > τ → full pass and memory reset; else warp memory (labels nearest, confidence nearest), 3b: context pass at `ctx_scale`, in non-moving cells per pixel the context label wins where its confidence ≥ the warped memory's, and the memory keeps the winner's confidence; moving cells: glimpses (replace rule), confidence = glimpse max prob.
  - Ledger components: `full`, `homography`, `motion`, `warp`, `context`, `fusion`, `glimpses`.
- [ ] **Step 1: Write the failing tests** (fixture data, `StubBackbone` or the `oracle_backbone` fixture, grid 12:2, `allow_any_frame_size=True`):
  - `test_frame_zero_is_the_full_pass`: equals `FullFrameMethod(backbone, scale=full_scale).predict` on frame 0.
  - `test_tau_zero_always_falls_back`: every frame's prediction equals the full pass and `last_step["fallback"]` is True for t > 0.
  - `test_a_static_clip_recomputes_nothing`: a clip whose frames are all frame 0 → `moved_cells == 0` for t > 0 and predictions equal frame 0's.
  - `test_predictions_never_hold_ignore` (Review Focus 2): a clip built by shifting frame 0 by 4 px per frame → no 255 in any prediction.
  - `test_3b_static_cells_take_the_more_confident_label`: with a context backbone that is more confident everywhere, non-moving cells equal the context prediction.
  - `test_reset_clears_the_memory`: after `reset`, the next frame is a full pass.

### Task 4: Per-frame caches and the exact replay (bounds included)

**Interfaces:**
